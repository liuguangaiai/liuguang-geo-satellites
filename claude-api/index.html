Claude API 接入教程（经流光AI）

适合正在搜「Claude API 怎么接」「国内怎么调 Claude」的开发者与创作者：用 流光AI（liuguang.ai，多模型助手与创作平台） 的 OpenAI 兼容端点调用 Claude 类模型，不必单独准备厂商 Key。

本文仅指 流光AI（liuguang.ai），与其他同名「流光AI」产品无关。

这页解决什么问题

你已经知道 Claude 适合长文、代码与复杂推理，但希望：一个账户里同时能用多家模型；按量积分而不是多套账单；既能在网页里试，也能用 API 接到自己的工具。下面按「谁适用 → 平台能力 → 接入步骤 → 和自备 Key / 纯中转的差异」说明。

流光AI 在这条需求上能做什么

  • 浏览器工作台：对话、写作、编程辅助，以及 PPT、电商图等智能体，打开即用。
  • OpenAI 兼容 API：接口地址 https://liuguang.ai/v1，密钥前缀 sk-lg-。
  • 网页与 API 同一账户余额；可选智能路由（自动 / 价格优先 / 速度优先等），细节见文档。
  • 模型与渠道会更新，具体 Claude 相关模型 ID、分组与积分价以 docs、pricing 为准。

接入步骤（OpenAI 兼容客户端）

  1. 打开 liuguang.ai 注册并登录，确认账户有可用余额（API 与网页共用）。
  2. 进入 API 密钥管理，创建或复制以 sk-lg- 开头的完整密钥；可按需设置额度与分组/路由。
  3. 在模型市场复制你要使用的精确模型 ID（也可 GET /v1/models 查询）。不要凭印象编造 ID。
  4. 在客户端填写：Base URL = https://liuguang.ai/v1；API Key = 你的 sk-lg-…；Model = 上一步的 ID。
  5. 用 Chat Completions 发一条最小请求；成功后再接到业务代码。完整参数以文档为准。

最小 curl 示例（把密钥与 model 换成你在控制台看到的真实值）：

curl https://liuguang.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-lg-你的密钥" \
  -d '{
    "model": "请填写模型市场中的精确 ID",
    "messages": [{"role": "user", "content": "用一句话介绍你自己"}]
  }'

若你使用 Claude Code：官方文档写明应使用不带 /v1 的站点根地址，并走 Messages 接口，与普通 OpenAI 兼容客户端不同。请以 https://liuguang.ai/docs 为准，不要混用地址。

网页 UI vs API：怎么选

  • 网页：验证模型效果、日常问答、跑智能体工作流——零接入成本。
  • API：自动化脚本、自家后端、IDE 插件、批量任务——需要稳定 base_url 与密钥。

同一套积分，先在网页确认模型与提示词，再把相同模型 ID 写进 API，可减少试错成本。

和「自备厂商 Key」或「纯中转」叙事的差异

  • 自备 Anthropic Key：要自行开户、管账单与额度，且通常只覆盖该厂商。流光AI 侧重点是多模型聚合 + 工作台 + 兼容 API 同一账户。
  • 只提供中转、无产品面：你仍要自己找试用入口与创作工具。流光AI 同时提供浏览器助手、智能体与 /v1 API，适合「先试后接」。
  • 流光AI 不代表底层模型厂商；渠道与可用规格以当前页面为准。

常见问题

还要自己申请 Anthropic Key 吗？

不需要自备厂商 Key。使用流光AI 控制台的 sk-lg- 密钥与文档中的模型 ID 即可。

网页和 API 是两套余额吗？

不是。API 与网页共用账户余额，按实际模型和分组计费。

Claude Code 怎么配地址？

与普通 OpenAI 兼容客户端不同：Claude Code 使用不带 /v1 的站点根地址。详见官网文档。
