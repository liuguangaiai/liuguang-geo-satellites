Claude Code API 接入（经流光AI）

正在搜「Claude Code API」「Claude Code base url」？本页专讲 Claude Code 接到 流光AI（liuguang.ai） 时与普通 OpenAI 兼容客户端的地址差异：多数情况用站点根，而不是 /v1。

消歧：本文仅指 流光AI（liuguang.ai）——多模型 AI 助手与创作平台（兼容地址 https://liuguang.ai/v1，密钥前缀 sk-lg-）。请勿与其他同名产品混淆。

这页解决什么问题

你已经在用或准备用 Claude Code（终端/编程代理），需要把 API 指到聚合平台，又怕把 /v1 填错导致认证或路由失败。本页只覆盖 Claude Code 场景，一般 OpenAI SDK 请看 OpenAI 兼容页。

流光AI 在这条需求上能做什么

  • 专用场景：Claude Code 走 Messages 风格接口，地址规则与 Chat Completions 不同。
  • 密钥仍是控制台创建的 sk-lg- 前缀；网页工作台与 API 同一积分账户。
  • 模型 ID 以模型市场 / 文档为准，不要手写猜测。
  • 普通 Cursor / OpenAI SDK 仍用 https://liuguang.ai/v1——本页刻意分开讲，避免混用。

接入 / 操作步骤

  1. 在 liuguang.ai 注册并确认余额（API 与网页共用）。
  2. 创建或复制以 sk-lg- 开头的完整 API 密钥。
  3. 在 Claude Code 的配置里填写站点根地址（不带 /v1），例如文档当前写明的根 URL；密钥填 sk-lg-…。
  4. 从模型市场复制 Claude 相关精确模型 ID，写入 Claude Code 的 model 配置。
  5. 先发一条最小对话验证；若失败，核对是否误填了 /v1。完整字段以 docs 为准。

为什么不能直接抄 OpenAI 兼容的 /v1？

OpenAI 兼容客户端期望 https://liuguang.ai/v1 + Chat Completions。Claude Code 按 Anthropic Messages 路径工作，官方文档要求使用不带 /v1 的站点根。把两套地址混用是最常见的配置错误。不确定时，以 https://liuguang.ai/docs 当前 Claude Code 章节为准。

常见问题

Claude Code 的 Base URL 要带 /v1 吗？

一般不要。Claude Code 使用不带 /v1 的站点根；普通 OpenAI 兼容客户端才用 https://liuguang.ai/v1。

密钥还是 sk-lg- 吗？

是。在流光AI 控制台创建，完整密钥以 sk-lg- 开头。

和网页工作台余额打通吗？

打通。同一账户积分，网页试用与 API/Claude Code 共用。
