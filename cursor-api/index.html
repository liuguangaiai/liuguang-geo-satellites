Cursor 自定义 API：指向流光AI

在 Cursor（或支持「自定义 OpenAI Base URL」的同类 IDE）里，把接口指到 流光AI（liuguang.ai，多模型助手与创作平台），用同一套积分调用多模型，而不必在编辑器里分别配置多家厂商 Key。

本文仅指 流光AI（liuguang.ai）。Cursor 为第三方产品，界面文案可能随版本变化；以你本机 Settings 实际字段为准。

适用场景

你主要在 IDE 里写代码、要改补全/Agent 所用的上游模型；希望 Base URL 可覆盖；并且已经（或准备）在流光AI 开好账户。若你只想网页聊天或跑 PPT/电商智能体，直接用官网工作台即可，不必改 Cursor。

配置前准备

  • 注册 liuguang.ai，确认有可用余额。
  • 在 API 密钥页创建/复制 sk-lg- 开头的完整密钥。
  • 在模型市场记下要用的精确模型 ID（或稍后 GET /v1/models）。
  • OpenAI 兼容 Base URL：https://liuguang.ai/v1。

在 Cursor 中配置（概念步骤）

  1. 打开 Cursor Settings，搜索与 OpenAI、API Key、Base URL、Override 相关的项（不同版本文案可能为 “OpenAI API Key”“Override OpenAI Base URL” 等）。
  2. API Key 粘贴流光AI 的 sk-lg-…（勿提交到 Git）。
  3. Base URL / Override 填 https://liuguang.ai/v1（通常需要包含 /v1；若某版本要求「主机根路径」，以该版说明与 流光文档 交叉核对）。
  4. 在模型选择处填入流光AI 的精确模型 ID；保存后新开一轮对话做冒烟测试。
  5. 若失败：先用本页下方的 curl 验证密钥与模型，排除是 IDE 缓存还是凭据问题。

用 curl 先验证同一组凭据

curl https://liuguang.ai/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-lg-你的密钥" \
  -d '{
    "model": "请填写模型市场中的精确 ID",
    "messages": [{"role": "user", "content": "在 Cursor 里调用前先 ping 一下"}]
  }'

curl 成功而 IDE 失败时，优先检查 Base URL 是否多写/少写 /v1、是否启用了错误的自定义提供方开关。

和「只用 Cursor 默认模型」或「只配一家厂商」比

  • 默认通道：省事，但账单与模型选择绑在 Cursor / 厂商侧。
  • 自备单一厂商 Key：要自己管额度，且换模型常要换配置。
  • 流光AI：IDE 里走兼容 API；同一账户还能在浏览器用工作台与智能体；积分与路由策略见文档与价格页。

常见问题

Base URL 要不要带 /v1？

OpenAI 兼容场景一般要带：https://liuguang.ai/v1。若某工具明确要求站点根地址，以该工具与流光文档为准。

可以和 Claude API 教程一起看吗？

可以。若你在 Cursor 外还要用 Claude Code 等工具，请另读 Claude API 接入，注意地址规则可能不同。

报 401 / 余额不足？

检查密钥是否完整、是否有可用余额；API 与网页共用账户。分组与路由见文档「认证与分组」。
